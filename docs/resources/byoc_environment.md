# ybm_byoc_environment (Resource)

The resource to register a BYOC (bring your own cloud) environment for PostgreSQL clusters. Registering returns an API key for the environment's agent; install the agent in your Kubernetes cluster with install_hint, and the environment becomes READY once the agent enrolls. The key is only returned by the apply that registers the environment: importing cannot recover it, and replacing or destroying the environment revokes it. An environment's name stays claimed after it is destroyed, so it cannot be registered again.

~> **Note:** This resource is behind a feature flag. Set the environment variable `YBM_FF_AEON_PG=true` to use it.


Creating the environment registers it and returns `agent_api_key` and `install_hint`. The environment stays `PENDING` until its agent is installed and enrolls with the key; `region`, `cloud_provider` and `k8s_version` are what the agent reports then. `placement` is passed to the agent by the install command, so set it before installing.

`agent_api_key` is only returned by the apply that registers the environment. Importing an environment cannot recover it, and replacing or destroying the environment revokes it. Keep it in a Kubernetes secret, as in the example, rather than only in Terraform state.

The environment's ID is derived from `name`: lowercased, with spaces, underscores and slashes turned into hyphens. A `name` change that derives the same ID, such as a change of case, is applied in place; any other change replaces the environment. After an import, `name` can be written as registered or as the ID.

!> **Warning:** Destroying or replacing the environment deregisters it and revokes the agent API key, and its name stays claimed, so an environment with the same name cannot be registered again.

## Example Usage

```terraform
resource "ybm_byoc_environment" "example" {
  name = "acme-prod"

  # Optional: where the environment runs, passed to the agent by the install command
  placement = "cloud"
}

# The environment, its agent and its clusters can come from one apply: the agent's
# install reads the API key from a secret, and clusters wait for the agent to enroll.
# The key is only returned by the apply that registers the environment, so keep it
# in the secret; importing the environment cannot recover it, and replacing the
# environment revokes it.
resource "kubernetes_namespace" "agent" {
  metadata {
    name = "ycp-agent"
  }
}

resource "kubernetes_secret" "agent_api_key" {
  metadata {
    name      = "amp-agent-api-key"
    namespace = kubernetes_namespace.agent.metadata[0].name
  }
  data = {
    "api-key" = ybm_byoc_environment.example.agent_api_key
  }
}

# install_hint lists every value the agent's chart needs, such as the image tag and
# the database it stores its state in; put them in agent-values.yaml.
resource "helm_release" "agent" {
  name      = "yb-amp-controller"
  chart     = "oci://quay.io/yugabyte/charts/yb-amp-controller"
  namespace = kubernetes_namespace.agent.metadata[0].name
  timeout   = 600
  values    = [file("${path.module}/agent-values.yaml")]

  set {
    name  = "agent.enabled"
    value = "true"
  }
  set {
    name  = "agent.ycpUrl"
    value = var.ycp_url # the agent.ycpUrl in install_hint
  }
  set {
    name  = "agent.envName"
    value = ybm_byoc_environment.example.environment_id
  }
  set {
    name  = "agent.placement"
    value = ybm_byoc_environment.example.placement
  }
  set {
    name  = "agent.apiKeySecret.name"
    value = kubernetes_secret.agent_api_key.metadata[0].name
  }
}

resource "ybm_byoc_storage_pool" "payments" {
  environment_id = ybm_byoc_environment.example.environment_id
  name           = "payments"

  # A failed install fails here at once rather than after the wait for the agent
  depends_on = [helm_release.agent]
}

output "agent_install_hint" {
  value = ybm_byoc_environment.example.install_hint
}
```

## Schema

### Required

- `name` (String) The name of the environment, 3 to 60 characters. Its environment_id is derived from it: lowercased, with spaces, underscores and slashes turned into hyphens. A change that derives the same ID, such as the case, is applied in place, so after an import the name may be written as registered or as the ID. Any other change forces a new environment.

### Optional

- `placement` (String) Where the environment runs, which the install command passes to the agent. Defaults to cloud. It only applies when the environment is registered.

### Read-Only

- `account_id` (String) The ID of the account this environment belongs to.
- `agent_api_key` (String, Sensitive) The API key the environment's agent authenticates with. Only available from the apply that registers the environment, and not after an import.
- `cloud_provider` (String) The cloud provider the agent reported.
- `environment_id` (String) The ID of the environment, derived from its name.
- `install_hint` (String) The command that installs the environment's agent.
- `k8s_version` (String) The Kubernetes version the agent reported.
- `region` (String) The region the environment's agent reported when it enrolled.
- `state` (String) The state of the environment, such as PENDING, ENROLLING or READY.

## Import

Import is supported using the following syntax:

```shell
# An environment is imported by its ID, which is its name lowercased with spaces,
# underscores and slashes replaced by hyphens. Its agent_api_key cannot be imported.
terraform import ybm_byoc_environment.example acme-prod
```
